## Proposed direction

- Product: Help badminton players register and tournament staff run games accurately.
- Character: Sporting, direct, composed.
- World: Clubhouse noticeboards, court lines and printed match cards; retain the existing navy/lime palette and Arial stack.
- Moments: Live scores and selected divisions carry emphasis; surrounding forms and navigation stay quiet.
- Signature: A restrained lime court-line marker for the current step or active game.

## Approved polish implementation

The user subsequently approved applying these suggestions to the live site. The release keeps the navy/lime brand and Arial stack. Screen-only CSS sets shared primary/secondary/ghost/danger action labels to 600 and status badges to 500 with sentence case and zero tracking. Registration uses 600 for its active step, 500 for shirt descriptions, 16px desktop progress gaps, 32px bottom spacing, 40px step circles and 48px fields. Tablet/phone progress uses 12px gaps, 36px circles and the existing compact 16px bottom margin to retain room for wrapped labels. The desktop shirt step uses 24px bottom spacing. Native radio/checkbox sizes, mobile input text, umpire scores/control sizes, projector scaling and print styles are retained.

The scoreboard hero's decorative circle is removed. Live cards use the normal quiet border and neutral card shadow; the status text still identifies live games. Submission guidance is shorter while retaining the instruction to keep the registration ID and private PIN. Four-photo guidance keeps the count, formats, size limit, upload timing and manual payment confirmation distinct.

The live organizer Setup view was observed in Brave before release. A fresh private tournament-state recovery file at revision 289 was downloaded and its SHA-256 wrapper digest verified. The previous successful deployment's logs confirm Worker `racketeers`, D1 `racketeers-db`, private bucket `racketeers-payments` and Worker version `e583582f-a07b-42a8-85c0-95786db02963`. Recovery is source revert/redeployment or Worker rollback with the same bindings; extra receipt objects can remain private. This is not a complete D1/R2 backup or restore test. No production data mutation is required for this release.

## Four-photo feature

New registrations can select up to four screenshots, add selections over multiple picks and remove selections before submitting. Existing groups can add photos into vacant numbered slots or explicitly replace an existing photo. All linked players share the same four-photo allowance. Each input and converted PNG remains limited to 2 MiB. Individual image requests preserve the existing request-size protection.

Organizer cards expose every uploaded photo for viewing/downloading; the existing confirmed delete action now removes all group photos. Signed exports open a gallery for multiple photos. Legacy primary receipts remain readable. OCR still reads the primary image and saves one review per payment group; the UI explicitly asks organizers to inspect every photo. Adding/replacing any photo changes the aggregate proof version, invalidating older reviews. Uploading never confirms payment.

Uploads are sequential. A failure can leave earlier photos saved; the error reports the completed count and asks the user to check saved photos before retrying. Photos remain outside tournament JSON. No database migration or production access was performed.
